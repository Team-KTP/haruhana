# 002. AI 모델 선택 — Gemini vs OpenAI, 환경별 분리 전략

> **카테고리**: 설계결정  
> **날짜**: 2026-04-06  
> **관련 PR**: -

---

## 배경

서비스에는 두 가지 AI 호출 지점이 있다. 하나는 **문제 생성**, 다른 하나는 **AI 채점(피드백)**이다. 초기에는 Google Gemini 2.0 Flash를 단일 모델로 사용했지만, 서비스 안정화 단계에서 "현재 모델이 최선인가?"라는 의문이 생겼다.

---

## 문제 / 목표

- OpenAI gpt-5.4-mini와 Google Gemini 2.5 Flash의 실제 응답 속도를 직접 측정하여 비교
- 두 기능(문제 생성, AI 채점)의 성격이 다른 만큼 동일 기준으로 평가하지 않기
- 비용과 UX를 동시에 고려한 환경별 최적 모델 결정

---

## Before — 단일 모델 사용

모든 환경, 모든 기능에 Gemini 2.0 Flash 단일 모델 사용.

```yaml
# application.yml (공통)
spring:
  ai:
    google:
      gemini:
        model: gemini-2.0-flash
```

**문제점**: Production에서 채점 기능의 응답이 느리다. 개발/테스트 환경에서도 유료 API 비용이 발생한다.

---

## 실측 비교

| 항목 | OpenAI GPT-4o-mini | Gemini 2.5 Flash |
|------|-------------------|-----------------|
| 문제 생성 | 약 6.5초 | 약 17초 |
| AI 채점(피드백) | **약 4.1초** | 약 10초 |
| RPM (무료) | 500 | 5 |
| RPD (무료) | - | 20 |
| 비용 | 유료 | 무료 플랜 존재 |

---

## 핵심 인사이트 — 기능마다 다른 지연 허용 범위

두 기능의 **사용자 경험 구조가 다르다.**

| 기능 | 처리 방식 | 사용자 대기 여부 | 지연 허용 수준 |
|------|---------|--------------|------------|
| 문제 생성 | 자정 배치 + 비동기 | 즉각 결과 기다리지 않음 | 높음 |
| AI 채점 | 제출 직후 확인 욕구 | 피드백 탭을 바로 열어 확인 | 낮음 |

Gemini 기준 채점 평균 10초는 GPT 대비 **2.4배 느림**. 채점 기능에서는 체감 차이가 명확하다.

**RPM 500은 충분한가?**
- 500 RPM = 초당 약 8.3 요청
- 문제 생성은 자정 배치 집중이지만, 현재 규모에서 짧은 시간 내 8건을 지속 초과할 가능성 낮음
- 채점은 사용자 제출 시 1건씩 발생 → RPM 병목 시나리오 아님

---

## After — 환경별 모델 분리

| 환경 | 모델 | 이유 |
|------|------|------|
| local / test / staging | Gemini 2.5 Flash (무료) | 기능 동작 검증 목적. 속도보다 비용 절감 우선 |
| production | OpenAI GPT-4o-mini | 사용자 체감 속도가 핵심. 채점 4.1초 vs 10초 |

```yaml
# application-staging.yml
spring:
  ai:
    google:
      gemini:
        model: gemini-2.5-flash

# application-prod.yml
spring:
  ai:
    openai:
      model: gpt-5.4-mini
```

설정 파일(`application-{profile}.yml`)로 AI 모델을 주입하여 코드 변경 없이 환경만 바꾸면 모델이 자동 전환된다.

**결과**: 개발/테스트 중에는 비용 0원으로 기능 검증, Production에서만 유료 모델 사용.

---

## 왜 이렇게 했는가

- "어떤 모델이 더 좋은가"가 아닌 **기능의 사용 흐름과 사용자 체감을 기준으로 요구사항을 정의**한 뒤 모델을 선택했다.
- 동일한 AI 기능이더라도 비동기(문제 생성)와 동기(채점)의 지연 허용 범위가 다르다.
- 환경별 관심사(비용 vs 속도)가 다르다는 점을 명시적으로 구분했다.

---

## 배운 점 / 회고

- 기술 선택에서 "무엇이 더 좋은가" 보다 "이 맥락에서 무엇이 더 적합한가"가 더 중요한 질문이다.
- 현재 OpenAI 4.1초도 절대적으로 빠른 수치는 아니다. "Gemini보다 덜 느리다"가 더 정확한 표현이다.
- **개선 과제**: 스트리밍 응답 방식으로 전환하면 첫 토큰이 도착하는 시점부터 UI에 점진적으로 표시 가능 → 체감 응답 속도를 크게 개선할 수 있다.
- Gemini 무료 플랜의 RPD(일일 요청 수) 20건 제한 → staging에서 반복 테스트 시 일 제한 도달 가능. 별도 테스트용 API 키를 관리하거나 핵심 시나리오만 선별하여 검증하는 방식으로 대응.
